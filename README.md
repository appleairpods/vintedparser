# Vinted Monitor Bot

Парсер, который следит за лентой новых объявлений Vinted и присылает
пользователям те, что подошли под их фильтры в чат с телеграм-ботом. 

## Как это устроено

Ключевая идея: **бот не опрашивает Vinted отдельно для каждого пользователя.**
Он забирает общую ленту свежих объявлений с постоянной частотой, а фильтры
применяет локально, у себя в процессе. Поэтому нагрузка на Vinted не зависит
от числа пользователей — что при 100, что при 15 000 она одинаковая.

```
Vinted API ──► Fetcher ──► Normalizer ──► Matcher ──► outbox (Postgres) ──► Telegram
  (по стране)                                ▲
                                       фильтры из БД
```

Vinted — это не один сайт, а десяток национальных площадок, и у каждой своя
лента. Поэтому на каждую включённую страну поднимается свой цикл опроса со
своей отметкой живости: бан или сбой одной не останавливает остальные.
Фильтр хранит список стран, и цикл забирает из базы только те фильтры, что
относятся к его стране.

Всё работает в одном процессе (`app/main.py`): по задаче на страну плюс
отправка из очереди, уборка старых записей, напоминания о подписке и сторож,
который жалуется админу, если какой-то парсер перестал приносить данные.

### Сколько стран можно включить

Vinted считает лимит запросов **по IP, а не по домену**, поэтому все страны
делят общий бюджет: `POLL_PAGES × страны / POLL_INTERVAL`. На практике четыре
страны по одной странице раз в 4 секунды работают, а по две страницы — уже
ловят 429. Нужно больше — поднимай `POLL_INTERVAL` или подключай прокси.

Отдельный компромисс: у крупных площадок (`de`, `fr`) за 4 секунды выходит
больше 96 объявлений, поэтому в логах у них постоянный `poll.gap` — часть
ленты бот не видит. Лечится теми же прокси либо более частым опросом.

## Структура

```
app/
  domain/            чистая логика без i/o: модели, матчинг фильтров, тарифы
  application/       сценарии: цикл опроса, разбор команды /add
  infrastructure/
    vinted/          единственная точка доступа к Vinted (клиент + нормализация)
    db/              модели SQLAlchemy и запросы
    telegram/        клавиатуры, тексты, хендлеры и отправщик уведомлений
  main.py            точка входа
migrations/          Alembic
tests/               тесты матчинга, парсера команд и нормализации
scripts/             спайк для быстрой проверки доступа к Vinted
```

## Запуск

### 1. Токен бота

Получи токен у [@BotFather](https://t.me/BotFather), свой Telegram id — у
[@userinfobot](https://t.me/userinfobot). Впиши их в `.env`:

```
BOT_TOKEN=123456:ABC...
ADMIN_IDS=123456789
```

### 2. Через Docker (рекомендуется)

```powershell
docker compose up -d --build
docker compose logs -f bot
```

Миграции применяются автоматически при старте контейнера.

### 3. Локально, без Docker

Нужен работающий Postgres. Если поднимаешь только базу в Docker:

```powershell
docker compose up -d postgres
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m app.main
```

Подключение для pgAdmin: `localhost:5432`, база/пользователь/пароль — `vinted`.

## Интерфейс

Под полем ввода закреплена постоянная клавиатура: новый фильтр, мои фильтры,
кабинет, пауза и «Ещё» для остальных разделов. Она не уезжает вместе с историей
чата, поэтому кнопки остаются доступны, даже когда идёт поток карточек.

Остальная навигация — inline-кнопки: фильтры, личный кабинет, подписка,
справка. Чтобы чат не превращался в ленту нажатий, эти экраны редактируют одно
и то же сообщение вместо отправки новых.

Фильтр создаётся диалогом: что ищем → страны с флагами → цена; бренд и
размер уточняются с экрана подтверждения по желанию. Цену я сравниваю как
есть, без конвертации: 50 злотых и 50 евро — разные деньги.

### Пауза

Уведомления выключаются кнопкой внизу экрана, кнопкой на любой карточке
объявления или командой `/pause`. Пауза не трогает фильтры и не копит
пропущенное: после включения приходят только объявления, появившиеся с этого
момента. Уже поставленные в очередь карточки при паузе удаляются — иначе они
продолжали бы приходить ещё несколько минут, и кнопка выглядела бы сломанной.

Пауза и блокировка — разные поля (`paused` и `is_active`). Иначе снятие бана
вернуло бы уведомления и тому, кто выключил их сам.

Команды оставлены как запасной путь — они удобны в отладке и незаменимы,
когда что-то сломалось:

| Команда | Что делает |
|---|---|
| `/menu`, `/help` | меню и справка |
| `/pause`, `/resume` | выключить и включить уведомления |
| `/add <фильтр>` | добавить фильтр одной строкой |
| `/list`, `/del <номер>` | фильтры |
| `/profile`, `/sub` | кабинет и подписка |
| `/admin`, `/stats` | админка (только админ) |
| `/grant <tg_id> <дней>` | выдать Pro вручную (только админ) |
| `/refund <charge_id>` | вернуть звёзды (только админ) |
| `/ban`, `/unban` | управление доступом (только админ) |

Однострочный синтаксис `/add`:

```
/add nike air max
/add куртка price:10-50
/add brand:Zara size:M price:-30
```

Слова без двоеточия ищутся в названии, бренде и размере. Модификаторы:
`price:мин-макс` (любую границу можно опустить), `brand:`, `size:`.

## Тарифы и оплата

| | Бесплатный | Pro |
|---|---|---|
| Уведомлений в сутки | 10 | без ограничений |
| Фильтров | 1 | 10 |

Лимиты заданы в `app/domain/plans.py`, цены — в `.env` (`SUB_STARS_30`,
`SUB_STARS_90`).

Оплата — звёздами Telegram (валюта `XTR`). Для цифровых товаров Telegram
другого способа и не разрешает, зато не нужны ни юрлицо, ни договор с
эквайрингом, ни вебхуки: факт оплаты приходит обычным апдейтом.

Сутки считаются по UTC. Квота проверяется в момент постановки в очередь, а не
при отправке — иначе накопились бы сообщения, которые всё равно не уйдут. Когда
лимит исчерпан, пользователь один раз за день получает сообщение об этом с
кнопкой подписки.

Возврат делается командой `/refund` по `charge_id` из таблицы `payments`;
Telegram разрешает вернуть звёзды в течение 21 дня. Вместе с возвратом
подписка снимается.

## Админка

Кнопка «⚙️ Админка» появляется в главном меню только у тех, чей id указан в
`ADMIN_IDS`. Доступ закрыт фильтром на уровне роутера, а не проверками внутри
хендлеров: так его нельзя забыть в новом экране.

Что есть:

- **Статистика** — пользователи, подписчики, заработок в звёздах, глубина
  очереди и время последнего успешного опроса (🟢 свежее двух минут, 🔴 нет).
- **Пользователи** — последние зарегистрировавшиеся и поиск по id или имени.
  В карточке видно тариф, расход квоты за сегодня, число фильтров и сколько
  человек заплатил; оттуда же выдаётся и снимается Pro, блокируется доступ.
- **Платежи** — последние поступления с кнопкой возврата. Возврат снимает
  подписку, иначе он превращался бы в подарок.
- **Рассылка** — текст с HTML-разметкой, предпросмотр с числом получателей и
  подтверждение. Уходит через тот же outbox, что и уведомления, поэтому не
  упирается в лимиты Telegram и переживает рестарт.

## Настройки

Все параметры — в `.env`, см. `.env.example`.

| Переменная | Смысл |
|---|---|
| `VINTED_REGIONS` | коды стран через запятую: `de,fr,pl,com` (см. `.env.example`) |
| `POLL_INTERVAL` | пауза между циклами опроса, сек |
| `POLL_PAGES` | сколько страниц ленты забирать за цикл (96 объявлений — максимум, который отдаёт API) |
| `VINTED_PROXY` | прокси для запросов к Vinted, пусто — прямое соединение |
| `SUB_STARS_30`, `SUB_STARS_90` | цена подписки на 30 и 90 дней, в звёздах |
| `LISTING_TTL_DAYS` | сколько дней хранить объявления |
| `MAX_LISTING_AGE_MINUTES` | не уведомлять об объявлениях старше этого возраста |
| `SEEN_TTL_HOURS` | сколько часов помнить id обработанных объявлений |

Про темп опроса: на `vinted.com` лента прирастает примерно на 15 объявлений в
секунду, а одна страница отдаёт максимум 96 позиций. Значения по умолчанию
(страница раз в 4 секунды) дают около полуторного запаса по ёмкости при 15
запросах в минуту.

Если в логах появляется `poll.gap`, значит за цикл не встретилось ни одного
знакомого объявления — Vinted публикует быстрее, чем мы забираем, и часть
ленты прошла мимо. Уменьши `POLL_INTERVAL`. Увеличивать `POLL_PAGES` менее
выгодно: соседние страницы перекрываются примерно на четверть, потому что
лента сдвигается прямо во время запроса.

## Разработка

```powershell
.\.venv\Scripts\python.exe -m pytest -q          # тесты
.\.venv\Scripts\python.exe -m ruff check .       # линтер
.\.venv\Scripts\python.exe scripts\spike_vinted.py www.vinted.com   # проверка доступа
.\.venv\Scripts\python.exe -m scripts.e2e_check  # сквозная проверка конвейера
```

Спайк — первое, что стоит запустить, когда бот перестал присылать объявления.
Он за секунду показывает, отдаёт ли Vinted данные вообще.

`e2e_check` заводит временного пользователя с широким фильтром, прогоняет два
цикла опроса и показывает, какие сообщения ушли бы в Telegram. Нужен поднятый
Postgres; тестового пользователя скрипт за собой удаляет.

## Важное про Vinted

Публичного API у Vinted нет, бот обращается к внутренним эндпоинтам сайта.
Практические следствия:

- **Схема может поменяться без предупреждения.** Тесты в `tests/test_normalizer.py`
  построены на реальном ответе и покраснеют раньше, чем бот начнёт слать пустые
  карточки.
- **Доступ может закрыться.** Сайт защищён DataDome. Сейчас `www.vinted.com`
  отдаёт данные при обычном TLS-импersonation, но на серверных IP
  (AWS, Hetzner, OVH) это, скорее всего, потребует резидентного прокси —
  для этого есть `VINTED_PROXY`.
- Весь доступ изолирован в `app/infrastructure/vinted/client.py`. Когда
  DataDome в очередной раз обновится, переписывать нужно только этот файл.

Сбор данных противоречит условиям использования Vinted. Проект учебный;
не собирай персональные данные продавцов и не перепродавай выгрузку.
